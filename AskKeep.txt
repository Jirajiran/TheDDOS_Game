1.ตารางขอบเขต + Place snap (ฐานแมพ — ดูผลลัพธ์ก่อน · ยังไม่มีแพ้ชนะ)

ชื่อในเอกสาร (แยกให้ชัด — เลิกเรียกทุกอย่างว่า chuck อย่างเดียว)
- Path = แผ่นพื้นแมพ 1024×1024 วางต่อเป็นโลก (อ้างอิง Asset/AssetSVG/Path.svg)
- L1 cell = 512×512 ภายใน Path (4 ช่องต่อ Path)
- L2 cell = 256×256 ภายใน Path (16 ช่องต่อ Path)
- L3 cell = 64×64 ภายใน Path (16×16 = 256 ช่องต่อ Path) = place เล็กสุด · พอดี Unit / Object 1 ช่อง
- BaseChunk = โซนคำนวณ/กฎรอบฐาน · ทับ Path · ไม่ใช่แผ่นโหลดแยก
- หมายเหตุ: ตัวเลข 800/400/200/100 ในแชท/blueprint เก่า = ถูกแทนด้วย Set A ด้านบน

Path วางแมพ
- เรียงแบบตาราง N×N ตาม input ขนาด (mod ได้ · มีขีดจำกัดไม่ให้โลก bloat)
  · ขนาด 1 → 1 Path
  · ขนาด 2 → 2×2 = 4 Path (ตัวอย่างภาพ: Path ต่อกัน 4 ใบ)
  · ขยายต่อได้ตามสูตรเดียวกัน
- วางจากมุมซ้ายบนของเว็บ
- กล้องเลื่อนได้ แต่ไม่หลุดนอกขอบตาราง
- ตัวอย่างลำดับ Path:
  1 2 3
  4 5 6
  7 8 9

ชั้นตรวจใน 1 Path (หารครึ่ง — ตั้งต้น 4 ระดับ · ไม่ล็อกคิดแค่ขนาด Path เดียว)
- L0 / Path ทั้งใบ 1024×1024 = ตรวจใหญ่สุด
- L1 512×512 = ตรวจย่อยรอง · จุดเชื่อม Path→Path
- L2 256×256 = เชื่อม/หักระดับกลาง
- L3 64×64 = เล็กสุด · หักละเอียดรอบสิ่งกีดขวาง · ปลายทางละเอียด
- ถ้ายึดคิดแค่ขนาด Path ทั้งทาง AI จะอึดอัด ไม่ยืดหยุ่น — จึงมี 4 ชั้นกลบจุดอ่อนชั้นบน

เมื่อไหร่ลงชั้น (กฎเดินหยาบ→ละเอียด)
- จุด spawn / จุดแรกใน Path: ใช้ตรงกลางระดับ L1 พอ
- เดินต่อไป Path/ช่วงอื่น: ดู L2 เป็นหลัก
- มีสิ่งกีดขวาง หรือต้องละเอียด: ลง L3
- ไม่ได้ใช้ L3 ทั้งแมพทุกก้าว — ทุกชั้นมีไว้กลบจุดอ่อนของชั้นบน

จุดเดิน Path→Path บน L1 (pivot ใหญ่ · ภาพจุดแดงใน Path)
- ใน 1 Path มีชุดจุด: 4 มุม + 4 กลางขอบ + 1 ตรงกลาง = 9 จุด
- ใช้เดินเข้า Path อื่น · ขอบนอกแมพที่ไม่มี Path ถัดไป = ปิดไม่คิดต่อ
- จุดกลาง = ของแถมกรณีพิเศษ / อ้างอิงใน Path
- pivot รองหักละเอียด = บนกริด L3 (64) · L2 เป็นตัวเชื่อมกลาง

ทดสอบ vs เล่นจริง (ผิว Path)
- ตอนทดสอบ: แสดงทั้งพื้นที่สี + ตัวเลขบน Path เพื่อเห็นขอบเขต/ลำดับชัด
- ตอนเล่นจริง (อนาคต): สี (และเลข debug) เปลี่ยน/หายได้ — ไม่ยึดสีทดสอบเป็นลุคสุดท้าย
- โครง Path (ขนาด+ตำแหน่ง) คงที่ · ผิวแสดงสลับทีหลังได้

Place / สิ่งก่อสร้าง
- ช่อง place = L3 64×64 · snap ลงกริด ไม่ลากพิกเซลลอย
- หนึ่ง Path = กริด 16×16 ของ L3 (256 ช่อง)
- Placeholder ทั่วไป: Asset/AssetSVG/PlaceHold/Object_01.svg (~64×64 โลก) ไส้เต็ม 1 place
- สิ่งก่อสร้างใหม่ = ลงทะเบียน type + อาร์ต · ขนาด 1×1 place หรือคร่อมหลายช่อง
- ทดสอบใช้สีเทา Object_01 · อนาคตสลับ skin ได้เหมือน Path
- หักของ: tryPlace สำเร็จ → consumeSlotItem ใน sim เท่านั้น (UI/Hub อ่าน count ไม่หักเอง)
- freeCraft = เฉพาะ craft/buy · ไม่ทำให้ place ฟรี
- Hub = กระจกแสดง state · วางของ = Input→Action→sim (ghost จาก match ไม่ใช่ DOM เป็นกฎ)

ฐาน (object) + BaseChunk
- ฐานวางจริง V1 = 3×3 ของ L3 (64) = ก้อน 192×192 รวม (แผน/โค้ดปัจจุบัน · ไม่ใช้ 2×2 เก่า)
- Path 1024 ไม่หายและไม่ถูกแทนที่ — เพียงมีโซนฐานซ้อนทับ Path สำหรับคิดปลายทางสุดท้าย
- BaseChunk (เหลือง) = โซนคำนวณ/กฎ · ศูนย์กลางที่ฐาน · ทับ Path กี่ใบก็ได้ (เช่น ทับกลางรอยต่อ 4 Path)
  · ไม่ต้องเป็นแผ่นโหลดแยก
- ในพื้นที่ที่ BaseChunk ทับ:
  · จุดแดง / จุดเดินแบบ Path (พอร์ต L1) ในโซนทับ = ปิดการใช้งาน
  · ใช้จุดเดินชุดใหม่ของ BaseChunk แทน · การทำงานแบบเดียวกัน (กราฟจุด→ช่วงเดิน→ปลายทาง)
  · นอกโซน / ไม่มีฐาน = ใช้จุด Path ตามเดิม
- ถ้าไม่มี BaseChunk แล้วใช้แค่ Path วางฐานชิดขอบ Path → กระจายจากขอบ Path พลาดมุมเล็กๆ / รอยต่อได้
  BaseChunk ทำให้ทุกทิศรอบฐานเท่ากัน ไม่มีขอบ Path บังคับในขั้นปลายทาง
- กัน spawn กลุ่มเกิดใกล้เกิน: ต้องอยู่นอกระยะ BaseChunk
- ฐานพัง → ปิด BaseChunk คืนจุด Path (เข้าโหมดไม่มีฐานตามข้อ 4)

- ลดทอน stun / knockback (แนว % 0–1)

- เกราะ (ชนิดกัน / % 0–1 / ช่องเดียว) → รายละเอียดที่ ClassBaseGun

3.ClassBaseGun
เชื่อม Unit: เกราะช่องเดียว · reload 0–1 · Action ยิง/ไม่ยิง · คนกับบอทส่ง Action ช่องทางเดียว

โหมดโจมตี (2 แบบ)
A) Projectile ตามเส้น Raycast (hybrid — โหมดหลักของปืน/จรวด)
   - กดยิง: ได้เส้นทางตรง (ทิศ + ระยะสูงสุด) จากแนว Raycast — ยังไม่จบดาเมจ
   - ซิม: จุดเดินตามเส้นด้วยความเร็วกระสุน · t ∈ [0,1] จากเวลา (speed * dt) ไม่ผูกจำนวนเฟรม
   - ตรวจช่วง t_เก่า→t_ใหม่ กันข้ามเป้าตอนเฟรมกระตุก · หลบหลังยิงได้ถ้าพ้นเส้นก่อนชน
   - Tracker บนจอ = โชว์อย่างเดียว ใกล้เคียงจุดซิมได้ ไม่ต้องตรงพิกเซล
   - ดาเมจที่ตัวกระสุนเมื่อชน collider (ปลาย/จุดซิม) ไม่ดาเมจทั้งเส้นทันทีแบบ hitscan
B) Melee ติด Object (หมัด ดาบ)
   - collider เปิด/ปิดตามแอนิเมชันหรือ stage
   - ขยับตาม object เจ้าของ
   - ส่งดาเมจ 1 ครั้งต่อการเข้าชน · ไม่โดนซ้ำจนกว่าจะออกแล้วเข้าใหม่

สเตตอาวุธ (ต่อชนิดใน data/dictionary)
- ระยะไกลสุด
- ดาเมจฐาน (baseDamage)
- ความเร็วกระสุน (โหมด A)
- cooldown / ยิงต่อเนื่อง
- จำนวนครั้งทะลุ (ชน collider ได้กี่ครั้งก่อนหมด)
- โหมด A หรือ B
- damageType (เข้าตาราง mult)

ชนิดดาเมจ / เกราะ (enum ชุดเดียวกัน — เทมเพลตยืดหยุ่น ไม่ล็อกจำนวนถาวร)
ตั้งต้น 4 ชนิด: Default | Bullet | Explosion | Lazer
- Default = ผิวหนัง / หมัด เนื้อ ดาบ (มักโหมด B)
- Bullet = กระสุน ดินปืน (มักโหมด A)
- Explosion = ระเบิด
- Lazer = ลำแสง
เกราะใส่ได้ช่องเดียว · มี armorType จากชุดเดียวกัน
ชนิดใหม่ในอนาคต = เพิ่มแถว+คอลัมน์ในตาราง ไม่เปลี่ยนสูตร

สูตรดาเมจ (ช่องละค่าเดียว — ไม่ซ้อนฝั่งยิง/ฝั่งรับ)
  damage = baseDamage * Table[damageType][armorType]
- Table = dictionary/enum 2 มิติ
- 1.0 = เท่าเดิม · >1 เพิ่ม · <1 ลด · 0 = กันสนิท (ถ้ามี)
- ความสัมพันธ์แบบ faction: A→B คนละช่องกับ B→A (ไม่บังคับสมมาตร)
- ทแยงมุม (ชนิดเดียวกันต้านตัวเอง) = นโยบายตั้งต้น สมเหตุสมผล

ตาราง mult ร่างทดลอง (ยังไม่ล็อกตัวเลขบาลานซ์ — โครงตั้งต้น)
แถว = โจมตี · คอลัมน์ = เกราะ
              Default  Bullet  Explosion  Lazer
  Default       1.00    1.25     0.90      0.75
  Bullet        1.25    0.75     0.85      0.50
  Explosion     1.40    0.90     0.70      0.80
  Lazer         1.60    1.40     1.10      0.60
แนวเรื่องคร่าวๆ: Default แทงเกราะ Bullet · Bullet แรงต่อเนื้อ · Lazer แรงต่อ Default/Bullet · ชนิดเดียวกันต้านตัวเอง

คำศัพท์กันสับสน
- Projectile ตามเส้น = ซิมกระสุนวิ่ง + ดาเมจตอนชน (ที่ใช้)
- Raycast ตอนยิงปืน = ใช้กำหนดเส้นทาง/ระยะ ไม่ใช่ hitscan จบดาเมจทันที
- Raycast ที่อื่น (เช่น ประตู Interact) = คนละระบบ อยู่ข้อ Unit

4.AI Final stage machice
สำคัญมาก · บอทคิดเป็น stage แล้วส่ง Action เข้า pipeline เดียวกับ Player (ไม่โกงกฎ / ไม่ข้ามระบบปืน·ชน·วางของ)
ค่าตัวเลขหลายตัวด้านล่าง = คาดเดาน้อยสุด / ตัวอย่าง ยังไม่ใช่บาลานซ์ล็อกตายตัว
อธิบายประกอบภาพตัวอย่าง 1–5 + คำตอบ Q1–Q3 ล็อกแล้ว (ดูท้าย Stage 1 และบล็อก Q)

บทบาทสองชั้น
- General (แผนที่/กลุ่ม): มองแมพแบบหยาบระดับ Path/L1 · วาง pivot · จัดเส้นทางกลุ่ม · ลดภาระไม่ให้ทุก unit ค้นทั้งโลก · ไม่ใช่ตัวละครที่เดินยิงเอง
- Unit stage: รับช่วงทาง · ตรวจศัตรู · ยิง · ถอย · เลี้ยวจำกัด · หลุดหนักแล้วสร้าง Local General · พอเข้า Path เป้าหมายแล้วเป็นฝ่ายค้น/ไล่ (และ BaseChunk ถ้ามีฐาน)
แนว "ค้นหา" = เดินตามโครงที่ General ปู เป็นหลัก ไม่ให้ทุก unit รัน BFS ทั้งแมพคนละฉบับ (ค้นกราฟแพง ให้อยู่ฝั่ง General หรือ Local ตอนจำเป็น)

--- โครงพิกัด (สอดคล้องข้อ 1 — Path / L1–L3 / BaseChunk)

- Path 1024 = หน่วยแมพใหญ่ · ภายในมี L1 512 · L2 256 · L3 64
- ตัวอย่างแมพขนาด 2: Path 2×2 = 4 ใบ · กริด L3 รวมเป็น 16×16 ช่อง
- General คิดหยาบระดับ Path/L1 · เชื่อม Path ด้วยจุด L1 (4 มุม + 4 กลางขอบ + กลาง)
- ลงชั้น: spawn ใช้กลาง L1 → ต่อไปดู L2 → ของขวาง/ละเอียดใช้ L3
- มีฐาน: เปิด BaseChunk ทับ Path · ในโซนทับปิดจุดเดิน Path ใช้จุด BaseChunk แทน (กลไกเดียวกัน)
- รายละเอียดชื่อและกฎเต็ม → ข้อ 1

--- วางตัวก่อนวางเส้น (ภาพ 2)

- สีแดง = เป้าหมาย Player (อยู่ Path เป้าหมาย เช่น Path 2)
- สีเหลืองในภาพเก่า = จุดเกิดกลุ่ม (ตัวอย่าง 3 กลุ่ม คนละ Path เช่น 4, 7, 9)
  หมายเหตุ: สีเหลืองในแนวฐานใหม่ = BaseChunk คนละความหมาย — ดูข้อ 1
- จำนวน unit ในกลุ่มยังไม่ล็อก · รู้แค่มีกี่กลุ่ม คนละจุดเกิด
- General สร้างเส้นต่อกลุ่มไปหา Path ที่เป้าหมายอยู่ ไม่ลากพิกเซลตรงไปที่ตัวแดงทั้งทางในขั้น General

--- Stage 1) ค้นหา / ตามเส้นทางกลุ่ม (General)

เป้าหมายที่ General จัดให้
- จัดโซ่ pivot ให้กลุ่มไปถึง Path ที่เป้าหมายอยู่
- อัปเดตเมื่อเกี่ยวกับ Path เป้าหมาย — ไม่ได้อัปเดตเกือบตลอดตามพิกัด Player ทุกขณะ
- ไม่สลับเส้นทางบ่อย: กันปลายทางถูกอัปเดต/หักซ้ำจน unit หลุดจากเส้นทางหลัก
- พอกลุ่มเข้า Path เป้าหมายแล้ว หน้าที่หลักเหลือที่ unit (กระจาย / มองหา / stage โจมตี · หรือ BaseChunk ถ้ามีฐาน)
- กลุ่มหลายเส้น (เช่น A1 A2 A3) ออกแบบให้ลงปลายทางชุดเดียวกัน / เข้า Path เป้าเดียวกันได้
  รวมรับรู้ตอนท้าย: ตัวใดเจอ Player ทั้งกลุ่มไล่ตามได้ — ไม่แย่งรีพาธกลางทางเพราะขอบสั่น

Player คาขอบ Path ใหญ่ (ล็อก + กันเส้นสั่น)
- ล็อก: ตอน Player อยู่ขอบระหว่าง Path General ยังถือ Path เป้าหมายเดิม
  จนกว่า Player จะเข้าใน L-cell ฝั่งใหม่ชัดเจน ถึงค่อยสลับเป้าหมายระดับ General
- ระหว่างนั้นให้ดู L1/L2/L3 เป็นตัวตัดสินละเอียด ไม่สลับไปมาตามเส้นแบ่ง Path
- ถ้ารู้ stage/โซนที่ Player อยู่แล้ว (โดยเฉพาะกลุ่มถึงปลายโซ่หรืออยู่ใน Path เป้า / BaseChunk)
  → unit ไปหา Player ในโซนได้ โดยไม่ต้องหักหรืออัปเดตเส้นทางหลักทั้งเส้นบ่อยๆ

ข้อเสนอช่วยคิด — รายละเอียดที่ยังไม่รู้ (แนะนำไว้ก่อน ยังไม่ล็อกตัวเลข)
- แถบ "คาขอบ Path": ใช้การอยู่บนเส้นแบ่ง Path + ดูว่า Player ยังไม่ครบอยู่ใน cell ฝั่งใหม่
  ไม่ต้องกำหนดพิกเซล hysteresis ตายตัวตอนนี้ · L-cell เป็นหน่วยตัดสินพอเป็นจุดเริ่ม
- สลับ Path เป้าหมายของ General เมื่อ: ศูนย์กลางตัว Player (หรือ hitbox) อยู่ใน cell ที่สังกัด Path ใหม่ทั้งช่อง
  ถ้ายังคร่อม/ยังอยู่ใน cell ฝั่งเดิม → คงเป้าหมายเดิม
- กลุ่มรวมรับรู้ตอนท้าย: ใช้ flag ระดับกลุ่ม "พบเป้าแล้ว" แชร์ในกลุ่มที่ลงปลายเดียวกัน
  ไม่จำเป็นต้องรัศมีรวมใหม่แยกจากระบบมองของ unit — ตัวที่เจอเป็นคนส่งสัญญาณกลุ่ม
- ถ้ารีพาธจำเป็นจริง (Player ย้าย Path ชัด): ปรับปลายโซ่/จุดเข้า Path เป้าเป็นหลัก
  พยายามไม่รื้อช่วงต้นที่กลุ่มเดินผ่านไปแล้วทั้งเส้น ถ้าทำได้ในเฟสถัดไป

สร้างเส้นทางต่อกลุ่ม ไม่ต่อทุก unit
- ตอน spawn ดูว่ามีกี่กลุ่ม แล้วสร้างเส้นทางกลุ่มละเส้น
- unit ในกลุ่มเดียวกันแชร์เส้นนี้
- จำนวนกลุ่ม × จำนวนต่อกลุ่ม (เช่น 3×5) = ตัวอย่างเท่านั้น ไม่ล็อก

วาง pivot แบบ pattern + snap (ภาพ 3)
- จุด spawn ของกลุ่ม = จุดเริ่มต้นโซ่ (เช่น A2)
- หัก pivot ไล่ไปหา chunk ที่เป้าหมายอยู่
- วางจุดตาม pattern แล้ว snap กับกลางช่องย่อย / กลางขอบ chunk
  ตัวอย่างกลุ่มจาก chunk 4 ไป chunk 2:
  · A2 = เริ่ม chunk 4 ตรงกลางของช่องย่อย (เช่น ช่อง 4.1)
  · B = เข้า chunk 1 ที่กลางขอบล่างสุด (1024/2 = 512)
  · C = เข้า chunk 2 ที่ขอบซ้ายกลาง (แนวตั้ง 1024/2 = 512)
- กลุ่มอื่นคนละโซ่ pivot แต่หลักเดียวกัน: เกิด → หักตาม chunk → เข้า chunk เป้าหมาย

จองเลนซ้าย / กลาง / ขวา (ไม่ใช่แค่วัดระยะสั้นสุด)
- ทิศเกิดของกลุ่มมีผลต่อการเลือกชุดจุด เช่น เกิดฝั่งซ้าย → คิดไปซ้าย/กลางก่อน ไม่กระโดดขวาไกลเกินโดยไม่จำเป็น
- ตัวอย่างทำไม A2 ไม่ไปจุดที่ระยะใกล้เท่าๆ กันแต่คนละฝั่ง (เช่น C1 แทน C2): เพราะทิศกลุ่ม + การจองเลนบังคับให้ไปชุดจุดของเลนตัวเอง
- กรณีหลายกลุ่มโซนฝั่งซ้าย (ลูปจองเลน):
  · กลุ่ม 1 ไปซ้าย → จองซ้าย
  · กลุ่ม 2 ไปกลาง → จองกลาง
  · ขวาไกลเกิน → ห้าม
  · กลุ่ม 3 วนกลับมาใช้ซ้ายได้ โดยนับจากตัวที่อยู่ใกล้ chunk เป้าหมายที่สุด
- ผล: ไม่ให้ทุกกลุ่มทับเส้นทางเดียว · กระจายเลนในโซน

สิ่งกีดขวาง + หักย่อยใน chunk ตัวเอง (ภาพ 4 · เชื่อม 5.Gen object Map)
- เส้นตรงระหว่าง pivot (เช่น B→C) ถูก object ขวางกลางทาง
- General ปรับจุดใหม่โดยหักย่อยภายใน chunk ปัจจุบันเป็นหลัก ไม่หักกระโดดไป chunk อื่นในขั้นตอนนี้
- ตัวอย่าง: B2 → B2.1 (ขึ้นหักกลางใน chunk เดิม) แล้วไปต่อ C2
- ความเป็นไปได้ถูกจำกัดด้วยทิศการเดินตาม chunk — บางทาง (เช่น ขยับลงสมมาตร) ระบบไม่มีทางที่ค่าจะเท่ากัน/ไม่อนุญาต จึงเลือกทางที่กริดรองรับ
- ระบบดู Player อยู่ chunk ไหน · วางจากตรงกลาง/ขอบใช้หัก

Unit รับแค่ช่วง A→B (คล้าย Region Trigger / Warcraft)
- เกิดมากับกลุ่ม ได้ช่วงแรก A→B
- เดินตามช่วงนั้น · ถึงโซน B / ชน area collider ที่ pivot → ได้ช่วงถัดไป B→C
- วนเป็น loop จนจบโซ่ หรือถูก stage อื่นแทรก (โจมตี / ถอย / Local)
- Area collider ที่จุด pivot ส่งค่าช่วงถัดไป · unit ไม่ต้องถือกราฟทั้งเส้นในหัวตลอด

รัศมีที่ทุกจุด A,B,C และจุดวางของแต่ละ unit
- ทุก pivot มีระยะรัศมีคุมตั้งแต่แรก
- unit ไม่กองจุดศูนย์กลางจุดเดียว: นำค่าตรงกลางไปคำนวณกับ % / modulo + ค่าที่ไม่คงที่ → จุดวางของตัวเอง
- ยังคุมให้อยู่ในรัศมีของช่วง · บางตัวลงไม่เหมือนกัน แต่ไปทางเดียวกัน
- ลงเสร็จ / เข้าเงื่อนไข → ได้ค่าให้ไปต่อ เป็น loop

เขตไม่ให้หลุดเส้น = Pi แบบองศา / sector (ภาพ 5)
- ไม่ใช่วงกลมเต็มใบไร้ทิศ: วงที่หันทิศ + Start Angle / End Angle กำหนดเนื้อใน
- Q1 ล็อก: จุดศูนย์กลางของช่วง A→B อยู่ที่ A (จุดเริ่มช่วง)
  วัดระยะทางไป B · ขยายรัศมีไปทางปลาย · ถึงปลายแล้วหยุดขยาย · หันแกนกลางไปหาปลาย · ปรับ fill ตามสูตร
- ลูปทั้งโซ่: A หัน+ขยายไป B → B เป็นจุดเริ่มหัน+ขยายไป C → … 
- จุดสุดท้ายที่ไม่มีจุดเชื่อมต่อ → ไม่ขยายต่อ เพราะไม่มีทางให้ไปต่อในโซ่ General
- ตัวอย่างองศา (คาดเดา): กรวยราว 45° รอบทิศปลาย · Start/End จากมุมกลาง ± ค่าองศา
- อาจให้ unit ใช้ Raycast แทนการถือพารามิเตอร์ Pi ครบทุกตัว — General/กลุ่มถือสูตรเต็มได้

ปลายโซ่ใน chunk เป้าหมาย (เช่น C2) — ยังไม่ใช่พิกัด Player
- ไม่มีจุดเชื่อมถัดไปในเส้น General
- ใช้ขอบอ้างอิงใน chunk เป็นทิศกระจาย (เช่น ขอบขวากลาง 1024/2 = 512) ให้ unit กระจายไปทางนั้นเพื่อหา Player
- ไปสุดไม่เจอ → กลับจุดปลายโซ่ (C2) แล้วกระจายตัวใหม่
- ตัวใดตัวหนึ่งเจอเป้าหมาย → ทั้งกลุ่มรู้ → เข้า stage ไปหาเลย
- ทั้ง chunk นั้นอยู่ในกรอบใหญ่ · chunk ย่อยเป็นตัวเสริมการกระจาย/ค้น

--- คิวเป้าหมาย + โหมดเส้นทาง (ฐาน / Player / จุดยึด)

โครงเป้าหมาย (โครงเดียวกัน)
- เป้าทุกชนิดใช้โครงร่วม: Player, Ally, ฐาน, จุดยึด ฯลฯ
- แต่ละเป้ามีลำดับความสำคัญของตัวเองจากค่าใน data (เช่น ของในตัวเยอะ, ชนิดเกราะ/อาวุธ, บทบาท Ally)
- เรียงคิวว่าสนใจใครก่อน — ไม่ hardcode รายชื่อใน if กระจาย
- ในแมพอาจมีหลายเป้าพร้อมกัน (อาจถึงราว 3 จุดสนใจ) แต่ไม่บังคับครบทุกชนิดเสมอ
- ตอนมีระบบฐาน: ในเกมมีฐาน 1 ที่เสมอ · Player 1–7 คน (รายละเอียด Host/จำนวน → 7.Menu + Hashing join)
- เคสหลาย Player ก็ยังฐานเดียว · สิทธิ์ตั้งโดย Host
- ภาพรวมโหมดแมพ/Host จะคุยแยกก่อนลงลึก 5.Gen object Map

เป้าติดพื้น vs เป้าเคลื่อนที่
- ล็อกพื้น (ฐาน, จุดยึด): เส้นทางล็อก Path ได้ · ประหยัด · สลับน้อย
- ฐาน object = 2×2 ของ L3 · มี BaseChunk ซ้อนทับ Path สำหรับปลายทางสุดท้าย (ข้อ 1)
- เคลื่อนที่ (Player, Unit): ยอมหักดิบไปหาได้ตามโหมด/เงื่อนไข · แต่ยังไปเป็นกลุ่ม ไม่แตกมั่ว

จุดยึด (ไอเดียเปิดไว้ — ยืดหยุ่นตามค่าความสำคัญ)
- ไม่ต่างจากจุด pivot / จุดปลายในโครงกราฟ
- ต่างหลัก: ไม่ส่งค่าต่อไปอีกจุดตามโซ่
- รอเงื่อนไขยึด (เช่น ต้องมี unit กี่ตัว · รับค่าอะไร) — จำนวน/สูตรยังไม่ล็อก เปิดไว้ปรับใน data
- ติดพื้น → ใช้โหมดเส้นทางประหยัดแบบเป้าไม่เคลื่อนที่ได้

งบ pivot
- ไม่ล็อกที่ 5 จุด · คิดเพดานขยายได้ราว 10 จุด (คาดเดา ปรับได้)

โหมด A — เป้าหมายหลักเป็น Player คนเดียว (หรือคิวชี้ Player เป็นหลักตอนมีเส้นล็อก)
- Unit เดินตาม General เข้า chunk เป้าหมายก่อน แล้วค่อยไล่ล่า
- ยกเว้น: Player อยู่ใกล้ก่อนถึงปลายโซ่ใน chunk → ไล่ล่าได้เลย
- วัด "ใกล้" จากตัว unit
- กลุ่มเข้า stage ไล่เมื่อมีตัวในกลุ่มเจอตามเงื่อนไข
- Player เดินเก่ง (หักเลี้ยว สลัด) + ออกนอกระยะ → สลัดกลุ่มได้ (ออกนอกระยะทำได้)
- Player วิ่งตรง ไม่มีสิ่งกีดขวาง → กลุ่มรับรู้แล้วเข้าไล่ · รัศมีรับรู้ติด · สลัดไม่หลุด · ตามได้ถึงสุดแมพ
- Player ตาย → กลุ่มอยู่จุดไหนก็เข้าสถานะเกี่ยวกับหลุดเส้นทางหลัก แล้วให้ AI จัดการต่อ (กันค้างสเตตไล่ศพ)

โหมด B — มีฐาน (ยังไม่พัง) + เป้าอื่น (Player ฯลฯ)
- ความสำคัญ: chunk ของฐานสำคัญสุดในชั้น General · Player/เป้าอื่นเป็นรองตามคิว
- ยังเข้า chunk ตามเส้นก่อน
- ไล่ตามเงื่อนไขแล้ว "ย้อนปลายทางที่กำหนด" = กลับจุดปลายโซ่ General เดิม (ใช้ตอนฐานยังไม่พัง)

โหมด C — ไม่มีฐาน (ฐานพังอย่างเดียวที่สลับเข้าโหมดนี้ตามล็อก)
- แมพไม่มีฐานตั้งแต่ต้น → ศัตรูใช้โหมด C โจมตี Player เลย (Player ไม่มีที่บัง/พยุง → ตายง่าย เป็นผลออกแบบ)
- ยอมหัก pivot หลายจุด · รับรู้ตำแหน่งเป้า
- ไม่สร้างปลายทางล็อกแบบประหยัดของฐานนิ่ง
- ไล่เป้าหมายใกล้สุดตามคิวความสำคัญตลอดเวลา · ยังดู chunk เป็นชั้นหยาบได้
- เข้า stage ไล่ล่าทันที → ไปหาเป้าโดยตรง · หลบสิ่งกีดขวางด้วย
- เหตุผล: ระบบแรกประหยัดเพราะฐานไม่ขยับบ่อย · พอไม่มีฐาน การล็อกปลายทางเสียมากกว่าได้

--- Stage 2) เผ้าระวัง → โจมตี

ตรวจจับ
- รัศมีวงรอบตัว (Pi) + พัด Raycast ด้านหน้า
- Raycast ไม่ใช่เส้นเดียว: เป็นลายเส้นรวมองศา เป็นแพทเทิร์น
  ตัวอย่าง: ~45° · เริ่ม 1 เส้นตรงกลางด้านหน้า → ขยายเป็น 3 → ขยายเป็น 5 เส้น
  ตัวเลของศาและจำนวนเส้น = ตัวอย่าง/คาดเดา ปรับใน data ได้
- มีรัศมี Pi ชั้นเล็กอีกชั้น: กันศัตรูถึงระยะประชิด แม้ด้านหลังนอกพัด Raycast
- เป้าหมายเข้าเงื่อนไขระยะ → เปลี่ยน stage ทันทีแล้วไล่ตาม

ไล่แต่ไม่ทิ้งเส้นกลุ่ม
- ตามเป้าหมายพอเป็นระยะ ไม่ไล่แบบสุดโลก
- Q3 ล็อก: ตอนอยู่ stage โจมตี การเช็ค "หลุดเส้น" ใช้ sector ของ General เป็นตัวตัดสินหลัก
- หลุดนอก sector → ย้าย stage กลับไปตามทาง
- ระหว่างเดินกลับเข้าจุด ยังหันไปยิงศัตรูได้
- ถ้าไม่ไกลมากจากเขต → ตามเป้าหมายต่อได้

เลือกเป้าหลายตัว
- จากที่ Raycast เห็น · นับความสำคัญสูงสุด
- ความสำคัญ = สูตรจากชนิดอาวุธ/เกราะใน data dictionary ที่มีอยู่แล้ว แค่ดึงมาดู เปรียบเทียบเร็ว
- ไม่เสียเวลาเลือกนาน · ยิงได้เลย
- เป้าสำคัญน้อย (เช่น ไม่มีอาวุธ) พึ่งรัศมี Pi เล็กกันประชิด

ติดทาง / งบเลี้ยว / โจมตีของขวาง / Local
- นอกจากการหักย่อยใน chunk โดย General (ภาพ 4) unit/กลุ่มยังมีงบเลี้ยวจำกัดตอนติดทาง
  ไม่ล็อกที่ 5 · เพดานคิดไว้ราว 10 จุด (ตัวอย่าง/คาดเดา)
- หมดแต้มเลี้ยว → บอกในกลุ่ม: หาคนเดียวไม่เจอ คนอื่นไม่ต้องหาต่อ → โจมตี object ที่ขวางทางเลย
- ถ้า object ทำลายไม่ได้จริง และหลุดทุกเงื่อนไข → ย้อนกลับจุดเริ่มต้นของทางเดิน รอเพื่อน / รอ spawn กลุ่มใหม่แล้วรวมกันอีก
- ถ้าไปรวมไม่ได้ ติดไปไหนไม่ได้ → เป็นอิสระต่อ General หลัก (หลุดการควบคุม) เพื่อไปให้ถึงปลายทาง

Local General (ระบบป้องกันในกลุ่ม)
- มีได้ต่อกลุ่ม · unit หลุดออกมาตัวเดียวก็สร้างได้
- แยกจากกลุ่มใหญ่ได้เพื่อไปรวมหรือไปต่อเอง · ขนาดกลุ่มไม่ได้ล็อกเสมอไป
- สร้าง General Local หาทางไปจุดปลายทาง · ถึงแล้วยกเลิก Local กลับ General หลัก
- ถ้ายังไม่ได้ → Local พยายามหาตำแหน่งเองต่อ

--- Stage 3) ถอย

- เข้า stage เมื่อ HP เหลือน้อย: เกณฑ์อ้างอิงอย่างมากราว 30% HP · เก็บใน data ต่อ type
- ไปอยู่ด้านหลัง unit ที่มากที่สุด หรือไปหา medic จนกว่า HP จะพอดี
- ถ้าไม่มี medic → ไปหา unit ที่แกร่งที่สุด ตามอาวุธ+เกราะ รวมเป็นค่าความสำคัญ ลูปไปเรื่อยๆ
- ถอยแล้วยังโจมตีได้ (ลูปถอย–โจมตี)
- ถ้าถอยไม่ได้ / ถูกบีบ (medic ตาย · ตัวแข็งตาย · เหลือตัวเบาๆ ใกล้ตาย จำนวนน้อย)
  → บังคับตัวสุดท้ายโจมตีโดยไม่ถอย พุ่งเข้าไป (melee/หมัด ก็ได้ ขอให้โจมตี)

--- สถานะค่าตัวเลข (กันสับสนตอนบาลานซ์ทีหลัง)

แนวคิดหลัก (ยึดเป็นเข็มทิศ)
- pipeline เดียวกับ Player · คิดเป็น stage
- ชื่อแยก: Path 1024 · L1 512 · L2 256 · L3 64 · BaseChunk โซนกฎรอบฐาน
- ลงชั้น L1→L2→L3 ตามจำเป็น · จุด L1 เชื่อม Path→Path (ขอบแมพปิด)
- มีฐาน: BaseChunk ทับ Path · ในโซนทับปิดจุด Path ใช้จุด BaseChunk แทน · กัน spawn ในโซน
- General จัดเส้นไป Path เป้าหมาย · อัปเดตเมื่อ Path เป้าหมายเปลี่ยนชัด ไม่ไล่พิกัด Player ทุกขณะ
- Player คาขอบ Path ใหญ่ → คงเป้าเดิมจนกว่าเข้า L-cell ฝั่งใหม่ · กันสลับบ่อย
- กลุ่มหลายเส้นลงปลายเดียวกันได้ · รวมรับรู้ตอนท้ายแล้วไล่ · ไม่รีพาธบ่อยจนหลุดเส้น
- path ต่อกลุ่ม · จองเลนซ้าย/กลาง/ขวาตามทิศเกิด + ลูปจอง
- ช่วง A→B + area trigger ส่งต่อ · หักย่อยสิ่งกีดขวางใน Path ตัวเอง (L2/L3)
- Pi sector ศูนย์ที่ต้นช่วง ขยายไปปลาย · ปลายโซ่กระจาย · เจอเป้าตัวเดียวทั้งกลุ่มรู้
- คิวความสำคัญเป้าจาก data (Player/Ally/ฐาน/จุดยึด โครงเดียว) · ติดพื้นประหยัด · เคลื่อนที่ยอมหักดิบแต่ยังเป็นกลุ่ม
- จุดยึด ≈ จุดปลายที่ไม่ส่งต่อโซ่ · รอเงื่อนไขยึด (จำนวน unit ฯลฯ เปิดไว้)
- โหมด A/B/C ตามมีฐานหรือไม่ · B ย้อนปลายโซ่ General · C ไล่ตรงเมื่อไม่มีฐาน
- โจมตี: หลุดเส้น = นอก sector General
- priority เป้าในระยะยิงจาก dictionary อาวุธ/เกราะ (ชั้นเลือกเป้าใกล้ตัว)
- Local ต่อกลุ่ม แยกได้แม้ตัวเดียว
- ถอยมีใน data ต่อ type

ตัวอย่าง / คาดเดาน้อยสุด (ปรับได้)
- แมพตัวอย่าง 3×3 chunk · 3 กลุ่มเกิดคนละมุม · จำนวน unit ต่อกลุ่มไม่ล็อก
- มุมพัด ~45° · Raycast 1→3→5 เส้น
- งบหัก pivot ไม่ล็อก 5 · เพดานราว 10
- ถอยที่ ~30% HP
- Player ต่อห้อง 1–7 (ไปข้อ 7)

    ล็อกเพิ่ม: Player คาขอบ Path → ถือเป้าเดิมจนกว่าเข้า cell ฝั่งใหม่

Q3. ตอนอยู่ stage โจมตี การเช็ค "หลุดเส้น" ใช้ sector ของ General เป็นตัวตัดสินหลัก

5.Gen object Map
ทางเลือกของแมพ — มีหรือไม่มีก็ได้
- ไม่มี: เกมรูปแบบหนึ่ง (เช่น Flat World) Path/Unit/ปืน/AI ยังเล่นได้โดยไม่มีชั้นทรัพยากรแมพ
- มี: สอดคล้อง PlaceHold · dictionary · สิ่งกีดขวางให้ General หักทาง · ดรอป/stack แบบเดียวกับของจาก unit
รายละเอียดโหมดโลก / สิทธิ Host → 7.Menu + Hashing join
ยังเป็นแนวคิดเริ่ม — ยังไม่ถึงขั้น Gen เต็มระบบ

เกิดตอนไหน
- Object พวกนี้เกิดตอน Gen แมพ ตามตั้งค่า Host
- Flat World = ไม่มี object พวกนี้ (แมพว่าง)
- World Type (ชื่อปรับทีหลังได้) = มี object ตามชนิดโลก / โควตาที่ตั้ง

โครง object (คล้าย Unit + ตารางแบบ ClassBaseGun)
- ลงทะเบียนใน dictionary / PlaceHold: typeId · ถูกทำลายด้วยอะไร · ดรอปอะไร · stack · (ต่อไป HP ชน ฯลฯ)
- สูตรทำลายใช้โครงเดียวกับอาวุธ:
  damage = base * Table[toolTier หรือ damageType][objectType]
- mult ในตารางยืดหยุ่นได้ทั้งช่องละค่า (รวมทางไม่เสีย HP เลย หรือต่ำจนไม่คุ้ม — บาลานซ์ต่อคู่)
- กลุ่ม Tool เดียว · มีหลายระดับขั้น ค่าทำลายต่างกัน · แยกในตารางกับชนิด object
- ชนิด object ที่เกี่ยวกับเก็บเกี่ยว/ทุบ มีน้อย — อย่างมากราว 4 อย่างตั้งต้น

ตัวอย่างตั้งต้น (ยังไม่ล็อกบาลานซ์)
- ต้นไม้: Tool ที่เข้าคู่ mult ≈ 1 · ไม่เข้าคู่ mult = 0 (หรือต่ำตามตาราง)
  ถูกทำลาย → ดรอปไม้ stack รวม เช่น 6 (ตัวเลขตัวอย่าง)
- หิน
- แร่เหล็กธรรมดา
- แร่เหล็กขั้นสูง
ตัวอย่างขั้น Tool (คาดเดา):
- ระดับ 0 (ขวาน/ค้อนปลายแนวกลุ่มเดียวกัน): ตัดไม้ได้ · หินได้ · แร่ไม่เข้า
- ระดับ 1 กลุ่มเดียวกัน: ทุบแร่ได้
รายละเอียดชนิด/ขั้นปรับใน data ได้

แนวคิดหลักตอน Gen (ต่อ 1 Path 1024×1024)
- ในแต่ละ Path ตั้งได้ว่า: ต้นไม้กี่อัน · หินกี่อัน · แร่กี่อัน · หรือไม่มีเลย
- กระจายด้วยระบบสุ่มแนว % / modulo + เปอร์เซ็นต์ความเป็นไปได้ใน 1 Path
- คิดราย Path ไม่กวาดทั้งแมพแบบไร้ขอบเขต
- สูตรสุ่มละเอียดยังไม่ล็อก — ล็อกแนวคิดโควตา/% ต่อ Path

สิ่งก่อสร้างจาก object รวมกัน (เปิดไว้ — เลื่อนหลังระบบหลักเสร็จ)
- ไอเดีย: รวม object ตาม dictionary/json · ระบุขนาดเอง เช่น L1 512 หรือ L2 256
- วางทับกริด L3 64 เป็น preset · visual บ้าน/สิ่งใหญ่ = custom จัดเอง
- โอกาสเกิดต่ำกว่าทรัพยากรทั่วไป · เน้นโหมด custom gameplay
- ลำดับเฟส: ทำระบบหลักให้เสร็จก่อน ค่อยคุยสเปกสิ่งก่อสร้างรอบนี้เต็มๆ

6.Ui UX show
เจาะลึก / สเปกยาว → ดูไฟล์ แผนงานและสถาปัตยกรรมระบบพัฒนาเกม.md
SVG เมนูสวยยังไม่มี — เฟสนี้ใช้ DOM/CSS placeholder ได้ · เน้น gameplay ก่อน
สถานะแผน: UI ละเอียด Deferred ได้ · แต่ App Flow ด้านล่างล็อกใช้ทดสอบ Local Host คนเดียว

App state (flow หลัก)
  BOOT → MENU → LOADING → PLAYING → RESULT → (กดปุ่ม) → MENU

BOOT (บังคับตอนเข้าเว็บ — ก่อนเมนูใช้งานได้)
- HTML เริ่มที่หน้า loading · เมนูยังกดไม่ได้จนกว่า bootReady
- งาน: ตรวจ DOM · prefetch asset ขนาน (timeout ต่อไฟล์ · พลาดไม่บล็อก) · sanitize autosave · แล้วค่อยเข้า MENU
- "Loading modules…" = dynamic import app.js · phase บน window.__theDdosPhase · watchdog ไม่ทับ Boot failed
- play-local.bat ใช้ serve_nocache.py (Cache-Control: no-store) ลดแคช ES module ค้าง
- cache-bust ที่ js/main.js?v=… + import app.js?v=…

LOADING (บังคับก่อนเล่นแมทช์)
- pools + world รันขนาน (overlap) แล้วค่อย occupancy/placeSlots
- timeout ต่อช่วง · ถ้า fail จะขึ้น label ชัด ไม่ค้างเงียบ
- มีแถบ loading (progress %)
- กัน GC สะดุดกลางแมทช์ (รายละเอียดโควตา pool → แผนสถาปัตย์)

PLAYING (HUD ขั้นต่ำเฟสนี้)
- ตัวบอกเวลาก่อน wave ถัดไป / wave ปัจจุบัน
- HP · hotbar Active · mute
- (ทางเลือกทีหลัง) มินิแมพ · build ghost เขียว/แดง บน L3
- ภายในแมทช์ยังมี Setup / Wave ตามกฎ V1 ในแผน (รายละเอียดไม่ซ้ำเต็มที่นี่)

RESULT (แพ้/ชนะ)
- แสดงเป็น panel ทับจอ ก่อน · ไม่เด้งเมนูเอง
- บังคับกดปุ่ม → กลับ MENU
- V1 (ดูแผน / game_pack / โค้ด): แพ้เมื่อ BaseBlock 3×3 พัง · ชนะเมื่อเคลียร์ wave เป้าหมาย (เช่น wave 7)
- แสดงสรุปสั้นได้ (เช่น wave ที่ถึง)

- SVG เป็นต้นฉบับ → เครื่องผู้เล่น bake เป็น bitmap ตอนเล่น
- หรือ Bitmap custom ใต้ Asset/Bitmap (pixel art วาดเอง)
- ชื่อไฟล์ ASCII · ลงทะเบียนแม็พกลาง ไม่ hardcode path กระจาย

ความละเอียด bake / ต้นฉบับ
- ยูนิตเรียบ / pixel: 32×32, 64×64, 128×128 ได้
- เพดานปลอดภัยประมาณ ≤256–512 · ไม่ bake 2000×2000
- ขนาดที่เห็นบนจอ ≠ ขนาดเท็กซ์เจอร์ (ขยายตอนวาด)

สเกลตอนวาด
- nearest-neighbor / imageSmoothingEnabled=false / image-rendering:pixelated
- อย่าอัปสเกลแล้วเซฟทับต้นฉบับ

Pool ยูนิต
- คุมพร้อมกันไม่เกิน ~100 (ประเภทเดียวหรือรวม)
- ตาย = ซ่อน + รีใช้ (รีเซ็ต hp / ตำแหน่ง) ไม่ลบทิ้ง
- Pool เดียว + typeId สลับรูปได้ · แคชรูปต่อประเภท (ไม่ต่อตัว)
- ไม่จำเป็นต้อง pool แยก 3×10 ถ้าโควตาร์วมเป็นก้อนเดียว

แยก 3 ขนาดเสมอ
1) ไฟล์ต้นทาง (SVG หรือ bitmap เล็ก)
2) ความละเอียดแคชตอนเล่น
3) ขนาดวาดในโลกเกม / บนจอ
