# Record — Goal ที่เก็บทีหลัง

สถานะ: **แบบแผนขั้นต้น** · ยังไม่มีในโค้ด (ไม่มีตัวบันทึกการเล่น · ไม่มีไฟล์ mod ของ Goal · ไม่มี editor ส่งออก)

คู่กับ `AI-Stage-Goals-and-Actions.txt` และ Mediator ปัจจุบัน  
Goal ที่รันอยู่แล้วเป็นรายการกำหนดไว้ในข้อมูล ไม่ใช่ Record

## ความหมาย

Record คือการเก็บการกระทำไว้เป็นของเรียนรู้ให้ AI ไม่ใช่สเตจที่รู้ Goal อยู่แล้วตอนบันทึก

ระหว่างบันทึกมีแต่การกระทำของผู้เล่น ระบบเก็บอินพุต เช่น ได้ทรัพยากรแล้วจึงวางฐาน ตอนนั้นยังไม่รู้ว่าหัวข้อคือสร้างฐาน

สูตร Goal ผูกกับ flow ของแผนที่นั้น จึงให้ mod กำหนดได้ ไม่ฝัง Goal ตายตัวในเกม

แนวอ้างอิงคือ Warcraft 3 ที่วาง Goal ของด่านไว้ล่วงหน้า ของที่นี่เก็บการกระทำก่อน แล้วค่อยตั้งชื่อ Goal ทีหลัง

## ตอนเอามาใช้

หัวข้อที่ตั้งทีหลังเป็น Goal ค้างไว้ สเตจไม่เรียกกันเอง ตัวกลางเลือกเป้าหมายที่น้ำหนักสูงสุดอันเดียวต่อเฟรม ภาพที่เห็นคือท่าต่างๆ ที่เข้า Goal นั้น

ขั้นใน Goal เรียงจากสิ่งที่มองเห็นได้ ไม่ใช่จากนาฬิกา ตัวอย่างสร้างฐาน:

- มีทรัพยากรพอ จึงวางบล็อก
- ยังไม่มี จึงไปหา หรือรอจนมี
- เวลารอแต่ละครั้งจึงไม่เท่ากัน

ถ้าถูกโจมตีหรือทางถูกกัน เป้าหมายนั้นหนักกว่าในเฟรมนั้น ก็ไปทำอันนั้นก่อน พอหมดเหตุ Goal เดิมยังอยู่ จึงถูกเลือกกลับมา

## เมื่อ Goal จบ

ฐานครบแล้ว Goal สร้างฐานจบ ไม่ขยายต่อเอง เพราะในบันทึกไม่มีขั้นนั้น

สิ่งที่สั่งต่อได้คือ Goal ใหม่ คือปกป้องฐานและบำรุงฐาน เพราะฐานมีแล้วและเสียได้ การขยายฐานคือ Goal สร้างฐานอีกชุดหนึ่ง ใส่เมื่อต้องการฐานที่ใหญ่กว่าเดิมเท่านั้น

## ขั้นที่ยังต้องคุยก่อนลงมือ

การทดสอบจริงไปอยู่กับ editor แผนที่ เพราะต้องวางของบนพื้นที่แล้ว export ไฟล์

ยังไม่กำหนด:

- ไฟล์ mod เก็บอะไร
- editor export เป็นรูปแบบไหน
