# editor — หน้าวางแมป (อ้างอิง Warcraft Editor)

อ่านก่อน:

- ตารางแมป พื้นที่ และตารางเกิด → `Doc/03_domains/map-path/README.md`
- ร่างยูนิต ชุดเริ่ม และ `active` → `Doc/03_domains/unit/README.md`

หน้านี้จัดของที่มีอยู่ลงบนแมป แล้วส่งไฟล์ JSON ออกไป หน้าเกมกับหน้าเอดิเตอร์คนละที่ เอดิเตอร์ไม่ใช่ที่เพิ่มไฟล์ศิลป์

## 1. สถานะหน้า

- หน้าทดสอบอยู่ที่ `editor.html` ไม่มีลิงก์จากเมนูเกม และไม่ต้องใส่คำลับ
- เปิดผ่าน HTTP ที่ `/editor.html` โหลดแพ็กกับ SVG ชั้นปิดไม่ครบจะไม่เปิดผืนแผนที่
- สร้างแมปครั้งเดียว ชื่อเริ่ม (untitled_map) ตาราง Path ด้านละ 1 ถึง 8 ช่องแล้วล็อก
- ลูกกลิ้งซูมแมป ลากขอบพื้นที่เพื่อย่อขยาย
- ส่งออกเป็นไฟล์เดียว นำเข้าไฟล์นั้นได้หลังโหลดภาพอีกครั้ง
- เว็บไม่เก็บงานถาวร แคชมีเฉพาะแท็บนี้ ปุ่ม (New map) ถามก่อนล้างแคชแล้วกลับจอสร้าง
- เสียงยังใช้ `audio.json` ของเกม
- เกมยังไม่อ่านไฟล์แมปนี้แทน `data/pack/`

## 2. สามชั้นของหน้า

หนึ่งแมปหนึ่งชุดไฟล์ คลังปืน สกิล และไอเท็มใช้ร่วมทุกแมป

2.1 ตารางเทียบ Warcraft

| Warcraft Editor | ชั้นนี้ | ไฟล์ | เอดิเตอร์ทำได้ |
|---|---|---|---|
| Import Manager / ไฟล์โมเดลและเสียง | (ชั้นปิด) | `js/assets/closedCatalog.js`, `data/pack/audio.json` | เลือก id ที่มีอยู่ คนสร้างเป็นคนเพิ่มไฟล์ |
| Object Editor: Unit, Item, Ability | (คลังชนิดของ) | `units.json`, `items.json`, `skills.json`, `weapons.json` | เปิดหนึ่ง id แล้วตั้งค่าในระเบียนนั้น |
| Terrain + วางของบนแมป | (แมปหนึ่งไฟล์) | `game_pack.json`, `areas.json`, `spawns.json` | วางพื้นที่ จัดแถวเกิด ตั้งทีมของแมปนี้ |
| Gameplay constants ที่ไม่ติดแมป | (การแสดงผลร่วม) | `presentation.json` | ไม่แก้จากแผงแมป |

## 3. การเปิดหน้า

- หน้าใหม่อยู่คนละไฟล์กับ `index.html`
- เมนูเกมไม่มีทางเข้า เปิด `/editor.html` ได้ตรงๆ
- ยังไม่มีบัญชีผู้เล่น

## 4. สองพื้นที่บนหน้า

- (ซ้าย) เป็นแผนที่ของแมปที่เปิดอยู่
- (ขวา) เป็นแผงของสิ่งที่เลือก

4.1 แผนที่

- ช่องละ 1024 พิกเซล จำนวนช่องล็อกตอนสร้าง
- ลูกกลิ้งซูม กด Space หรือปุ่มกลางเพื่อเลื่อนมุมมอง
- ลากพื้นที่สี่เหลี่ยม ชี้ขอบแล้วลากเพื่อย่อขยาย
- เลือกพื้นที่แล้วแผงแสดง (Action), (Condition), (Target area) และปุ่ม (Delete area)
- (Condition) กับ (Team) เป็นคอลัมน์ตั้ง กว้างไม่เกินแผง
- (Team) แสดงเมื่อเงื่อนไขเป็น (EnterArea) แต่ละแถวเป็นช่องเลือกทีม 1 ถึง 6 กับปุ่ม (X) และมีปุ่ม (Add)
- รายการอยู่ที่ (area.teams) และ (area.team) เท่ากับทีมแรก ซิมยังเทียบทีมแรก ทีมถัดไปยังไม่มีผลในซิม
- ยูนิตได้คำสั่ง (MoveTo) เมื่อทีมตรงกับพื้นที่ ผู้เล่นไม่ถูกสั่ง

4.2 แผงขวา

4.2.1 แท็บชนิด

หัวข้อบนแถบเรียงดังนี้

1. (พื้นที่)
2. (ตารางเกิด)
3. (ยูนิต)
4. (ปืน)
5. ชนิดไอเท็ม: (Block), (Turret), (Resource), (Item)
6. (สกิล)
7. (กติกา)

- แถบไม่เลื่อนแนวนอน หน้าหนึ่งอยู่ได้ประมาณ 4 ถึง 5 ชื่อ พร้อมปุ่มลูกศร
- แท็บซ้ายคือ id จริงของชนิดนั้น ชื่อยาวอ่านจาก `title`
- ช่อง (ID) แก้สตริงนั้นแล้วทุกจุดที่อ้างตามไป
- ของใหม่ที่กด (+) เป็นชิ้นร่างของชนิดบนแท็บนั้น กด (Apply) ครั้งเดียวแล้วชนิดล็อก
- ของที่มีอยู่แล้วเปิดแผงของมันเลย และไม่มีช่องให้เปลี่ยนประเภทอีก
- ปืน สกิล และไอเท็มมีปุ่ม (Delete) กล่องยืนยันถามก่อน แล้วจึงลบ id นั้นและแท็บซ้าย

(Block) รวม id ของ Block, Door, Generator, Factory และ Base

- รางแบ่งหัวชั้นตามประเภทนั้น ปุ่มบอกรหัสกับประเภท
- ชิ้นใหม่เลือกชนิดแล้วกด (Apply) ครั้งเดียว
- Door, Generator, Factory และ Base ไม่ได้อยู่บนแถบบน
- (Wire) กับ (Heal) ไม่ใช่ชนิดบล็อก ระเบียนเก่าที่ยังมีธงนั้นแสดงเป็น (Block) และธงในไฟล์แพ็กไม่ถูกลบ
- บล็อกธรรมดามีช่อง (Skill) เลือกสกิลของแมปนี้ได้ รวม (WIRE) กับ (HEAL)

(Item) รวม Shield ปุ่มบนแถบชื่อ (Item)

- ชิ้นใหม่เลือก Armor หรือ Shield แล้วกด (Apply) ครั้งเดียว
- ชิ้นที่ล็อกเปิดแผงของชนิดนั้น Shield ไม่ได้อยู่บนแถบบน
- แผงเกราะมีเปอร์เซ็นต์กันดาเมจต่อชนิดจากตาราง (ArmorType) และช่อง (bonusHp) ค่า (damageReduction) เดิมยังอยู่
- แผงโล่คง (shieldPierceCost) ข้อความบนแผงบอกว่ากระสุนเป็นฝ่ายขอทะลุและโล่เป็นฝ่ายเรียกราคา

(Weapons) รวมระเบียนปืนและไอเท็มชนิด (TOOL)

- ชิ้นใหม่เลือก (Gun) หรือ (Melee) แล้วกด (Apply) ครั้งเดียว
- ปืนใช้ช่องปืนเดิม พรีวิวยังเป็น (Default_skin_1) ถือปืนนั้น
- (Melee) ใช้ช่องที่มีอยู่ของ (Tool) คือ (toolTier), (harvestDamage), (structureDamage), (meleeRole) และช่องที่เหลือบนระเบียนเครื่องมือ
- ไม่มีแท็บ (Tool) บนแถบบน
- ไม่มีแท็บ Weapon ของไอเท็มถือ
- แถวชุดเริ่มที่เป็นปืนเลือก id จากชีตปืน แถวชนิดอื่นเลือก id จากชีตไอเท็ม
- สกิลใหม่มี (Effect)
- ไอเท็มร่างนอกแท็บ Block และ Item ไม่มีช่องเปลี่ยนชนิด
- ปืน Normal เป็นได้หลาย id เช่น M1991, AK47, Sniper แต่ใช้แผงเดียวกัน
- ช่อง model เป็นกลุ่ม SVG จาก `WEAPON_BTN_ART` ค่าเริ่ม `Weapon_Colt_1911` เมื่อไม่มีกลุ่ม
- ช่องท่าถือเป็น `hold_Gun` หรือ `hold_Gun_2`
- ปืนเดิมแสดงค่าจากตารางศิลป์ และเขียนลงระเบียนเมื่อมีการเปลี่ยนช่อง
- เกมที่เล่นอยู่ยังอ่านศิลป์ปืนจาก `WEAPON_BTN_ART`

(Resource) รวมทรัพยากรกับกระสุนที่ id ขึ้นต้น (AMMO_)

- ไม่มีแท็บ (Ammo) บนแถบบน
- เป้สามชั้นไม่ได้อยู่แท็บนี้
- ปืนเลือกกระสุนจากรายการนี้ได้

แท็บ (Skills) แบ่งหัวชั้นตามชนิดเอฟเฟกต์

- เอกสารแมปมีสกิล (WIRE) กับ (HEAL) ถ้ายังไม่มี ช่องของ (WIRE) คือการทะลุ ช่องของ (HEAL) คือรัศมีรักษา
- ยูนิตเลือกสองสกิลนี้ในช่องสกิลได้ เกมที่เล่นอยู่ยังไม่ยิงหรือรักษาตามสกิลนี้
- (BACKPACK_T1), (BACKPACK_T2), (BACKPACK_T3) อยู่หัวชั้น (Backpack) ท้ายรางนี้ ช่องถูกปิด ไม่มีปุ่มเพิ่ม ไม่มีลบ ไม่มี (Apply) ค่า (backpackTier) กับ (backpackBonusSlots) คงเดิม

(Turret) ใช้ช่องใน `TURRET_RECORD` คือ HP เกราะ รัศมีจับ และค่าป้อมที่เหลือ พร้อม `weaponId` จากปืนที่มีอยู่ Apply ของป้อมใหม่ยังเขียนธงวางของป้อมให้ระเบียนใช้ได้

4.2.2 ยูนิต

แท็บ (Unit) เป็น asset ที่เตรียมไว้

- แผงนี้ไม่รู้ (ทีม)
- แผงนี้ไม่รู้ว่าคนหรือบอทเป็นคนคุม
- ทีมและจุดเกิดของคนอยู่ที่แถว (Host) กับ (Player) ในข้อ 4.2.3

ลำดับช่องบนแผง

1. `id`, `model`, `startingLoadout`, `skills`, `currentSlot`
2. `hpRange` เป็นคอลัมน์เดียว ของค่าต่ำกับค่าสูง
3. เป้าหมายกับธงพฤติกรรมอยู่ล่าง
4. ไม่แสดง `defaultWeapon` กับ `hasPassiveShield`

ชุดเริ่มและพรีวิว

- `active` ติดได้ที่เกราะและโล่ ชนิดเดียวกันได้ชิ้นเดียว ชิ้นที่สองไม่ถูกสวม
- ปืนเป็นของในช่อง `currentSlot` คือช่องที่ถือปืน
- สกิลได้สามช่อง หัวคอลัมน์เขียนครั้งเดียว แต่ละแถวเป็นช่องเลือกกับ Remove
- ของเริ่มเรียงหัว Item กับ Count ครั้งเดียว
- แผงมีแถว (Drop) เป็น id จากแท็บ (Resource) รวมกระสุน, จำนวน, และปุ่ม (X) พร้อมปุ่ม (Add) เก็บในรายการ (drops) ซิมยังไม่ทำของหล่นจากยูนิต
- พรีวิวยูนิตใช้กลุ่มเดียวกับช่อง model (model.unit.default_1) คือ (Default_skin_1) และ (model.unit.default_2) คือ (Default_skin_2)
- ลำดับชั้นจากโมเดลเดียวกันคือของล่าง แขนของโมเดลนั้น ปืน ตัว แล้วของบน ไม่แปะแขนจากกลุ่ม (Action_hold_Gun) ทับสกินอื่น
- ใต้รูปบอกช่องปัจจุบันกับไอเท็มนั้น และเกราะหรือโล่ที่ active
- กล่องพรีวิวกว้างเต็มคอลัมน์ สูงคงที่ จัดกลาง ภาพใช้ `preserveAspectRatio` แบบ meet
- แท็บ (Weapons) แสดง (Default_skin_1) หนึ่งตัวในท่าถือของระเบียนปืนนั้น ไม่ใช่ก้อนสีอย่างเดียว

4.2.3 การเกิด

แถวเวฟบอทยังเรียง (Wave), (Time), (Team), (Area) แล้วบรรทัดถัดไปเป็น (Unit) กับ (Count) ยูนิตมาจาก id ในชีตยูนิตของแมปนี้ ปุ่ม (Remove) ของแถวยูนิตและปุ่ม (Delete row) ยังเป็นข้อความ

แถวคนเล่นคนละชนิดกับเวฟ และคนละเรื่องกับ (Ally)

- รางมีแถว (Host) ตั้งแต่สร้างแมป และตอนเปิดไฟล์เก่าใน (ensurePlayerSpawns) ลบแถว (Host) ไม่ได้
- (Host) มีคนเดียว แถวนั้นมีช่องเลือกยูนิตอันเดียวกับเลขทีม
- แถว (Player) เพิ่มด้วย (+) ได้ตามจำนวนทีม โดยไม่หักที่นั่งของ (Host)
- (Host) เลือกเลขทีมซ้ำกับแถว (Player) ได้ แถว (Player) ด้วยกันยังไม่ใช้เลขทีมซ้ำ แต่ละแถวมีช่องเลือกยูนิตกับทีม ลบแถว (Player) ด้วยปุ่ม (Delete row)
- ทั้งกลุ่มทีมผู้เล่นมีตัวเลือกเดียว เป็นมิตรกันทั้งกลุ่ม หรือ (Friendly Fire)
- ทุกแถวมี (Area) ถ้ามีพื้นที่อยู่แล้วแต่แถวยังว่าง ให้ใช้พื้นที่แรก ถ้ายังไม่มีพื้นที่เลย จุดเกิดเป็นกลางตาราง (Path)

4.2.4 ป้อมและฐาน

พรีวิว (Block), (Turret) และ (Base) ใช้ (SizeView) เป็นช่อง 1×1 ในรูปเดียวกันกับปืน

- ก้อนสีเท่าช่อง (SizeView) ของกลุ่มปืนนั้น
- ชิ้นที่มี (weaponId) วางปืนในกรอบเดียวกับก้อน ไม่แยกเป็นกล่องสีกับรูปปืนคนละที่
- ชิ้น (Block) ที่ไม่มีปืนแสดงเฉพาะก้อน 1×1
- แท็บ (Weapons) ไม่ใช้ก้อนสีนี้ แสดง (Default_skin_1) ถือปืนของระเบียนนั้น
- แผง (Block) มีแถว (Drop) เป็น id จากแท็บ (Resource) รวมกระสุน, จำนวน, และปุ่ม (X) พร้อมปุ่ม (Add)
- แถวแรกเขียน (dropItemId) กับ (dropCount) แถวที่เหลืออยู่บนระเบียนของเอดิเตอร์

4.2.6 คราฟต์บนระเบียน

สวิตช์ (Craft) อยู่บนระเบียนของแท็บ (Weapons) รวมเครื่องมือ, (Block), (Turret), กระสุนที่เปิดจากแท็บ (Resource) และ (Item) ค่าอยู่ที่ (editorCraft) ของระเบียนนั้น

- ปิดแล้วเฉพาะกล่องคราฟต์เป็นสีเทา ช่องค่าเกมของเกราะยังแก้ได้
- เปิดแล้วแต่ละแถวเป็น id จากแท็บ (Resource) รวมกระสุนที่ขึ้นต้น (AMMO_), จำนวน, และปุ่ม (X) ในแถวเดียวกัน พร้อมปุ่ม (Add)
- ชิ้นชนิดอื่นบนแท็บ (Block) และชิ้น (Shield) บนแท็บ (Item) ได้สวิตช์เดียวกัน
- ค่านี้ไม่เขียน (craft.json) และเกมที่เล่นอยู่ยังไม่ใช้สูตรนี้

4.2.5 ทีมและกติกา

ทีมเป็นของแมป คัดลอกจาก `game_pack.json` ตอนสร้าง

- ช่อง (Team count) ตั้งแต่ 1 ถึง 6 กำหนดความยาว `teams` แถว (Nature) อยู่นอกจำนวนนี้
- เลขสูงขึ้นเพิ่มทีมท้ายแถวด้วย id ถัดไป `hostileTo` ว่าง และ `allyTo` ว่าง
- เลขลดลงตัดทีมท้าย เครื่องหมายของทีมที่เหลือคงเดิม
- แต่ละทีมมีช่องชื่อ รายการ (Hostile) และรายการ (Ally) เพิ่มได้หลายแถว แต่ละแถวเลือกทีมอื่นที่มีอยู่
- ทีมที่ไม่อยู่ในรายการคือไม่ถูกมาร์คว่าเป็นศัตรูหรือพันธมิตร
- `seatCap` 12 คือเพดานที่นั่งตอนผู้เล่นสู้กันเอง ไม่ใช่รายการทีม และไม่ล็อกว่าทีม 1 เป็นผู้เล่น
- พื้นที่ (EnterArea) มีทีมของตัวเอง คนละเรื่องกับทีมของแถวเกิด

แท็บ (Rules) มีรางสามชื่อคงที่ ลบไม่ได้

- (Rule) มีเฉพาะตัวเลขแมตช์
- (Player) มีจำนวนทีม ชื่อทีม รายการ (Hostile) และรายการ (Ally) ที่นั่งคนจริงยังไม่ล็อกทีม เมนูเลือกทีมหรือล็อกทีมเป็นงานภายหลัง
- (ArmorType) เป็นตารางตัวคูณ สำเนาจาก `damage_matrix.json` เก็บบนเอกสารแมป แถวคือ (damageType) คอลัมน์คือ (armorType) ชื่อนี้เป็นชุดเดียวที่ช่องของปืนและบล็อกใช้ เกมที่เล่นอยู่ยังอ่านไฟล์แพ็กเดิม
- แถว (Nature) ล็อกไว้นอกจำนวน 1 ถึง 6 ไม่ใช่ที่นั่ง (Host) หรือ (Player) ไม่มีรายการ (Hostile) หรือ (Ally) ของในทีมนี้คือทรัพยากรบนแมป
- แถว (Hostile) กับ (Ally) ให้ช่องเลือกทีมกับปุ่ม (X) เรียงต่อกันในแถวเดียว
- ปุ่ม (Remove) ของชุดเริ่ม สกิล และแถวเวฟ และปุ่ม (Delete area), (Delete row), (Delete) ยังเป็นข้อความ
- ค่าเหล่านี้เก็บในไฟล์แมป เกมที่เล่นอยู่ยังอ่าน `rules.json`

## 5. ส่งออก

- ส่งออกได้ไฟล์ JSON ของแมปนี้ และไฟล์คลังเฉพาะใบที่แก้
- นำไปวางทับใน `data/pack/` แล้วเปิดเกม
- เกมไม่ได้เปิดไฟล์จากหน้าเอดิเตอร์เอง มันอ่านแพ็กในโฟลเดอร์นั้นผ่าน `pack_manifest.json`
- กล้อง มุมภาพ และของดรอปอยู่ `presentation.json` ทุกแมปใช้ร่วม แผงแมปไม่เขียนไฟล์นี้
