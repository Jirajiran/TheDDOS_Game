 Program Function (Functional Thinking) คือการเปลี่ยนมุมมองจากการเขียนโค้ดสั่งให้บอท "เปลี่ยนสถานะไปมา" มาเป็นการมองสมองของบอทเป็น เครื่องจักรแปลงข้อมูล (Data Transformation Pipeline) ที่รับค่าสภาพแวดล้อมเป็น Input แล้วคำนวณคืนค่าการตัดสินใจออกมาเป็น Output โดยไม่เข้าไปแก้ไขค่าตัวแปรในโลกของเกมโดยตรง   1. หลักคิด 3 ข้อของการออกแบบฟังก์ชันให้ Bot คำนวณFunction as Mapping (รับ Input คืน Output ที่แน่นอน): ในทางคณิตศาสตร์และ Functional Programming ฟังก์ชันคือความสัมพันธ์ที่รับ Input เข้ามาประมวลผลแล้วคืนค่า Output ใหม่ออกไป เช่น ฟังก์ชัน CalculateDamage(60, 15) ที่แปลงค่าพลังโจมตีและป้องกันให้กลายเป็นค่าความเสียหาย 45 เมื่อนำมาใช้กับบอท ฟังก์ชันคำนวณจะทำหน้าที่เพียง "คิดเลขแล้วส่งคำตอบกลับ" (Pure Function) โดยห้ามสั่งลด HP ห้ามสั่งวาร์ป หรือเปลี่ยนค่า GameObject ภายนอกด้วยตัวเอง   Context-Free Transformation (แปลงข้อมูลโดยไม่ยึดติดตัวตน): ฟังก์ชันคำนวณที่ดีไม่จำเป็นต้องรู้บริบทหรือตัวตนของวัตถุ เช่น ฟังก์ชัน CalculateRemainingHP(currentHP, damage) ไม่ต้องรู้ว่า HP นี้เป็นของ Player หรือ Enemy แต่ต้องการรู้เพียงตัวเลข currentHP กับ damage เพื่อคำนวณเป็นค่า HP ชุดใหม่ ในระดับสมองบอท ฟังก์ชันคำนวณคะแนนจึงไม่ควรสนว่าบอทเป็นอาชีพอะไร แต่รับเพียงตัวเลขจาก Blackboard (เช่น hpRatio, distance, baseWeight) แล้วแปลงเป็นคะแนน priority   Continuous Transformation (ต่อท่อคำนวณเป็นลำดับขั้น): การตัดสินใจที่ซับซ้อนของบอทเกิดจากการนำฟังก์ชันขนาดเล็กหลายตัวมาเชื่อมต่อกันเป็นขั้นตอนต่อเนื่อง โดยนำ Output ของฟังก์ชันหนึ่งไปเป็น Input ของฟังก์ชันถัดไป เช่น นำ Attack และ Defense เข้า CalculateDamage เพื่อหา Damage จากนั้นส่ง Damage พร้อม Current HP เข้า CalculateRemainingHP เพื่อคำนวณเป็น New HP   2. เปรียบเทียบวิธีคิด: แบบ State เดิม vs แบบ Program Functionมิติการออกแบบการคิดแบบ Stateful / Imperative (FSM เดิม)การคิดแบบ Program Function (Functional)หน้าที่ของโค้ดตรวจสอบเงื่อนไขแล้วสั่งเปลี่ยน State หรือแก้ค่าตัวแปรทันทีรับข้อมูลชุดหนึ่งเข้ามาคำนวณ แล้วแปลงเป็นข้อมูลชุดใหม่   การผูกติดกับข้อมูลโค้ดมักผูกกับตัวตน เช่น เช็คว่าเป็น Player หรือบอทสายไหนแยกขาดจากตัวตน รับเฉพาะค่าตัวแปรที่จำเป็นต่อการคำนวณ   โครงสร้างการทำงานใช้ if-else ซ้อนกันหลายชั้นและกระโดดข้าม State ไปมาต่อท่อฟังก์ชันเป็นลำดับขั้นชัดเจน (Input → Transform → Output)   การทดสอบและดีบักยาก เพราะผลลัพธ์ขึ้นอยู่กับลำดับการเปลี่ยน State ก่อนหน้าง่าย เพราะหากใส่ Input ชุดเดิม จะได้ Output เดิมเสมอ3. ขั้นตอน:   อ่านข้อมูลและคัดกรอง (Sense & Filter): ดึงสถานะปัจจุบันของบอทและเป้าหมายรอบตัวจาก Blackboard โดยควรเลือกใช้โครงสร้างข้อมูลแบบ Hash Table อย่าง Dictionary<TKey, TValue> หรือ HashSet<T> ในการเก็บและค้นหาข้อมูลเป้าหมาย เพื่อให้ตรวจสอบสถานะได้รวดเร็วคงที่ในระดับ $O(1)$   แปลงข้อมูลเป็นคะแนน (Transform to Priority): ส่งค่าตัวเลขจาก Blackboard เข้าฟังก์ชันคำนวณของแต่ละ Goal (baseWeight + eventBoost + factors) เพื่อแปลงข้อมูลสถานการณ์ให้กลายเป็นตัวเลขคะแนนความสำคัญ   เลือกผู้ชนะและจับคู่การทำงาน (Select & Map Stage): หา Goal ที่ได้คะแนนสูงสุด (argmax) แล้วใช้ Dictionary<TKey, TValue> แปลง Goal นั้นให้กลายเป็น Stage ผ่านตาราง GoalToStage ด้วยความเร็ว $O(1)$ (หรือหากต้องการให้ระบบจัดเรียงลำดับความสำคัญของตัวเลือกตลอดเวลา สามารถใช้โครงสร้าง Balanced Tree อย่าง SortedDictionary<TKey, TValue> หรือ SortedSet<T> ที่เรียงลำดับให้อัตโนมัติในระดับ $O(\log n)$)   แปลงแผนการเป็นคำสั่ง (Action Transformation): ส่งข้อมูลเป้าหมายบน Blackboard เข้าฟังก์ชันของ Stage ที่ถูกเลือก เพื่อคำนวณและคืนค่าลิสต์คำสั่ง Actions[] (MOVE, AIM, FIRE) ออกไปให้ระบบเกมนำไปสั่งงานตัวละคร4. ตัวอย่างการเขียนฟังก์ชันคำนวณของ Bot แบบต่อท่อตัวอย่างการเขียนฟังก์ชันแยกย่อยที่รับ Input แล้วคืน Output // ไม่สนใจว่าบอทคือใคร รู้แค่ตัวเลขปัจจัยที่ส่งเข้ามา
static int CalculateEngagePriority(int baseWeight, int eventBoost, float distance, float maxRange, bool hasTarget)
{
    if (!hasTarget) return int.MinValue; // ไม่มีเป้า ให้คะแนนต่ำสุด
    int proximityBonus = (int)(Math.Max(0, 1.0f - (distance / maxRange)) * 100);
    return baseWeight + eventBoost + proximityBonus;
}

// ขั้นที่ 2: Function เลือก Goal ผู้ชนะแล้ว Mapping ไปเป็นชื่อ Stage
static string ResolveActiveStage(Dictionary<string, int> goalScores, Dictionary<string, string> goalToStage)
{
    string bestGoal = "REACH_PATH_GOAL";
    int highestScore = int.MinValue;

    foreach (var pair in goalScores)
    {
        if (pair.Value > highestScore)
        {
            highestScore = pair.Value;
            bestGoal = pair.Key;
        }
    }
    return goalToStage[bestGoal]; // ค้นหา Stage ใน O(1)
}

// ขั้นที่ 3: นำ Output ของแต่ละขั้นมาต่อท่อเข้าด้วยกัน (Continuous Transformation)

// Pure Function: รับเฉพาะ Input (config, unitState, bbSnapshot) -> คืนค่า Map ของคะแนน priority
function evaluateGoalPriorities(config, unitState, bb) {
  const scores = {};
  const hpRatio = unitState.hp / Math.max(1, unitState.maxHp);

  for (const goal of config.allowedGoals) {
    // 1. Input พื้นฐาน: baseWeight + Σ eventBoost[cite: 2, 3]
    const base = config.baseWeight[goal] ?? 0;
    const boost = bb.decision.eventBoosts[goal] ?? 0;

    // 2. Input สถานการณ์: คำนวณ factors และเช็คเงื่อนไขตัดสิทธิ์ (-Infinity)[cite: 1, 2]
    let factorScore = 0;

    if (goal === 'ELIMINATE_PLAYER' || goal === 'ELIMINATE_TARGET') {
      if (!bb.decision.combatTargetId) {
        scores[goal] = -Infinity; // ไม่มีเป้าใน Blackboard ตัดสิทธิ์ทันที[cite: 1, 2]
        continue;
      }
      const lockBonus = bb.decision.combatLockTimer > 0 ? 150 : 0; // กันอาการเปลี่ยนเป้าไปมา[cite: 1, 2]
      const proximityBonus = Math.max(0, 100 - bb.decision.targetDistance);
      factorScore = lockBonus + proximityBonus;
    } 
    else if (goal === 'SEEK_HEAL_POINT') {
      if (hpRatio > config.thresholds.retreatHpRatio || bb.survival.seekX === null) {
        scores[goal] = -Infinity; // เลือดยังไม่ต่ำหรือไม่มีพิกัดจุดฮีล[cite: 1]
        continue;
      }
      factorScore = (1.0 - hpRatio) * 200; // ยิ่งเลือดน้อย ยิ่งอยากไปจุดฮีล[cite: 1, 2]
    } 
    else if (goal === 'SURVIVE_RETREAT') {
      if (hpRatio > config.thresholds.retreatHpRatio) {
        scores[goal] = -Infinity;[cite: 1]
        continue;
      }
      factorScore = (1.0 - hpRatio) * 150;
    }

    // 3. รวมผลลัพธ์เป็นคะแนนสุทธิของ Goal นี้[cite: 2, 3]
    scores[goal] = base + boost + factorScore;
  }

  return scores; // Output ส่งต่อไปให้ argmax เลือก activeGoal[cite: 2, 3]
}
